# QEMU VM Manager

Веб-приложение для управления виртуальной машиной QEMU с Debian 13 (Trixie).
Из браузера можно включить, перезагрузить и остановить ВМ, а также работать
в её консоли -- через serial-порт или по SSH.

## Как это устроено

- **Образ ВМ** -- официальный Debian 13 genericcloud (сборка `20261001-2618`).
  Пользователь, пароль и SSH-ключ задаются через cloud-init (`seed.iso`).
- **Backend** -- Python, FastAPI. Запускает QEMU 11.0.5 как дочерний процесс и управляет
  им по протоколу QMP через unix-сокет.
- **Frontend** -- React (JavaScript), терминал на xterm.js. Статику раздаёт nginx,
  он же проксирует `/api` и `/ws` в backend.

## Развёртывание

Нужны только Docker и Docker Compose. Команды выполняются в Linux
(на Windows -- внутри WSL).

```bash
git clone https://github.com/techworkne/vm_manager.git
cd vm_manager
```

Если на хосте есть KVM (файл `/dev/kvm`), запускайте с ускорением:

```bash
docker compose -f docker-compose.yml -f docker-compose.kvm.yml up --build
```

Если KVM нет, подойдёт обычный запуск. ВМ будет работать в режиме эмуляции (TCG),
это заметно медленнее:

```bash
docker compose up --build
```

После запуска откройте в браузере <http://localhost:8080>.

Первая сборка занимает около 10 минут: QEMU 11.0.5 компилируется из исходников.
Повторные сборки быстрые -- Docker берёт готовый результат из кэша. Проверить версию
в работающем контейнере:

```bash
docker compose exec backend qemu-system-x86_64 --version
```

При первом старте backend сам готовит образ ВМ: скачивает базовый образ Debian
(около 340 МБ), создаёт SSH-ключ, `seed.iso` и диск. Это занимает пару минут
и зависит от скорости сети. Результат хранится в томах Docker, поэтому следующие
запуски быстрые.

Остановить сервис:

```bash
docker compose down
```

Удалить вместе с диском ВМ и ключом (при следующем запуске ВМ создастся заново):

```bash
docker compose down -v
```

## Использование

- **Включить:** запускает ВМ
- **Перезагрузить:** жёсткая перезагрузка ВМ
- **Остановить:** корректно выключает ВМ; если она не выключилась за 30 секунд -- завершает принудительно
- Индикатор справа вверху: текущее состояние ВМ, обновляется раз в 2 секунды
- Вкладка **Serial:** консоль ВМ через serial-порт: виден лог загрузки и приглашение `login:`
- Вкладка **SSH:** SSH-сессия в ВМ; пока ВМ загружается, терминал ждёт и рисует точки
- **Переподключить:** открывает соединение терминала заново

Данные для входа в ВМ через serial-консоль:

- логин: `user`
- пароль: `user`

По SSH вход выполняется автоматически по ключу, пароль вводить не нужно.
У пользователя `user` есть `sudo` без пароля.

Время загрузки ВМ после нажатия «Включить»: с KVM -- около 15 секунд,
без KVM -- от одной до нескольких минут.

## API backend

- `POST /api/vm/start` -- запуск ВМ -- старт процесса QEMU с флагом `-S`, затем `cont`
- `POST /api/vm/reboot` -- перезагрузка -- `system_reset`
- `POST /api/vm/stop` -- остановка -- `system_powerdown`, по таймауту `quit`
- `GET /api/vm/status` -- состояние -- `query-status`
- `WS /ws/serial` -- serial-консоль
- `WS /ws/ssh` -- SSH-консоль
